# Scope and evaluation contract

This is a simulation-only, state-based research baseline for PickCube-v1.
RGB remains recorded for visual inspection; it is not an input to this first model.
Completion means the following stages run locally and are committed separately:

1. Clean collection and reproducible replay (completed before this plan).
2. Episode-separated data splits and a self-supervised next-pose predictor.
3. Threshold calibration using clean data only and reproducible perturbed replay.
4. Locked held-out evaluation, persistence/constant-velocity comparisons, and a report.

The original 20 episodes remain in data/pickcube. The expanded dataset in
data/pickcube100 uses the same official demos and collection settings.
Split by original episode identity, with fixed random seed 42:
60% train, 10% validation, 15% calibration, 15% test. No frame/window splitting.
Do not combine both datasets, which contain duplicate source episodes.

The causal GRU observes joint positions/velocities, current tool/cube poses,
goal offset, previous observed pose motion, and the intended action. It predicts
one control step (50 ms) ahead. The model learns a correction to constant velocity.
Pose targets include both positions and rotations; quaternion signs are equivalent.
All normalization comes from training data. Validation selects the checkpoint.
Neither calibration nor test data participates in training or checkpoint selection.

Calibration uses validation error scales and clean calibration episode maxima;
the alarm threshold is chosen without any perturbed data. Record episode-level
clean false alarms as well as per-step rates. With few calibration episodes,
do not claim a certified low false-positive rate.

Test perturbations are predeclared, simulator-only interventions:
- Shift the cube 8 cm in world +x at 35% of the saved action sequence.
- Override the gripper command to fully open from 55% onward.
- Hold arm joint targets for 10 control steps starting at 55%.

Each held-out initial state also receives an unperturbed control replay.
Keep intended and actually applied actions separately. Perturbations are applied
after prediction input is available and before the corresponding physics step.
Only the initial state is restored; later states are generated by physics.

An injected perturbation is NOT itself a ground-truth task failure. Report:
- Whether the final ManiSkill task success criterion is met.
- Whether/when a residual alarm occurs, including premature alarms.
- Detection delay relative to the known injection time (not a proven failure onset).
- Recovered perturbations separately from terminal failures.
- Paired clean checks and baseline detectors, calibrated independently.

The result is a runnable proof of concept, not a claim of real-robot readiness,
generalization to unseen tasks, or reliable detection of every manipulation failure.
